# Message Queue

One session runs one active turn at a time. While that turn is still going you can keep typing and sending: the message joins a queue and is picked up automatically once the previous turn settles. Instead of being pushed back with "a task is already running", and without dropping anything. Implemented with zero dependencies in `util/agent/queue.mjs`.

## Behavior

- **Enqueue**: a submission made while a turn is active gets a `turn_queued` receipt (with its `position` in line and the original `input`), and the client draws a compact queue bar above the composer
- **Relay**: once the previous turn settles (`turn_completed`, `turn_failed` or an abort all count as settling), a non-empty queue pumps the next item; it only really starts when its turn comes, and its events go to its own SSE stream
- **Idempotent**: every submission carries an `opId` (generated by the web client; the server fills one in when absent). A repeated `opId` returns the same receipt, opens no second stream and runs nothing twice, so a network retry cannot run your sentence twice
- **Runs even when nobody watches**: if the client disconnects while queued, the item still runs when its turn comes and its events are discarded
- **Side conversations never queue**: `/btw` keeps its original 409 mutual-exclusion semantics with the main turn

## State machine

`queued` (waiting) → `running` (executing) → `done` / `failed` (in-memory terminal states); `held` is an explicit user hold that needs a promote to move on.

State lives in `<data directory>/queue.json` (temp file + rename for an atomic write) and only persists `queued` / `running` / `held`; `done` / `failed` are trimmed before writing. A corrupt queue file falls back to an empty queue with a warning instead of blocking what you type. Per-session queue cap: 200 items.

Restart recovery: a `running` item that was killed mid-flight falls back to `queued` and is re-run by the pump; `held` items are preserved as-is.

## Where to operate

| Surface | Operations |
| --- | --- |
| Web | queue bar above the composer: see position and text, send now, remove |
| Terminal | `/queue` (list) / `/queue send <n>` (move to the front and send) / `/queue drop <n>` (remove) / `/queue clear` (clear all) |
| HTTP | `GET /api/agent/queue/:id`, `POST /api/agent/queue/promote`, `POST /api/agent/queue/remove` |

An item that is already executing cannot be deleted remotely: deleting it would leave no stream to receive its result, so use stop instead (`POST /api/agent/abort`). Removing a queued item pushes `turn_cancelled` (`reason: 'removed'`) to its stream.

## When you will not notice it

A submission made while the session is idle is just an ordinary turn and never enters the queue. Only "the previous turn is still running" causes queuing. While queued you can keep editing the composer, switch sessions, or check which position your message is at — the relay replays the original request snapshot (model, permission mode and thinking toggle included).
