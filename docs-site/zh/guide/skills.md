# 技能系统

技能 = 一个目录：`SKILL.md`（frontmatter + 正文）加可选的 `references/` `scripts/` `assets/` 附属文件。系统按**三层渐进式披露**加载，日常上下文里只留名称与描述。

## 三层渐进式披露

| 层 | 内容 | 何时进上下文 | 成本 |
| --- | --- | --- | --- |
| L1 目录 | `name` + `description` | 会话开始常驻 | 约 50–100 token/技能，总量受 4000 token 预算约束 |
| L2 指令 | `SKILL.md` 正文 | 技能被触发时整篇加载 | 建议 <5000 token、正文 <500 行 |
| L3 资源 | `references/` `scripts/` `assets/` 等附属文件 | 正文引用到才读 | 未访问零成本 |

L2 激活时服务端返回结构化包裹：正文、技能的**绝对目录**、附属资源清单（只列名与体积，不预读内容）。模型据此用 `read_file` 以绝对路径读需要的附属文件——技能目录是文件工具的**只读白名单根**，写工具仍禁锢在会话工作目录。`scripts/` 里的脚本用 `shell` 以绝对路径执行，沿用 shell 的超时与权限三档。

## 调用方式

1. **显式**：任意客户端输入 `/<技能名> [参数]`（终端命令、网页输入区 `/` 调色板同源；服务端单点解析）
2. **隐式**：模型判断用户请求与某技能描述匹配时，自行调用 `skill` 工具

`implicit: false` 的技能只保留显式入口，不进模型可见的目录。

## 存放位置

| 位置 | 来源 | 说明 |
| --- | --- | --- |
| `skills/` | 内置 | 随仓库分发，当前 4 个 |
| `<数据目录>/skills/` | 用户 | 自定义技能，重启后生效 |

同名时用户目录覆盖内置。加载采用宽松校验：`description` 超长、正文超 500 行、`name` 与父目录名不一致都只告警不拒载；缺 `name` / 缺 `description` / 正文为空才跳过。

## 目录结构

```text
my-skill/
├── SKILL.md            # 必需：frontmatter + 指令正文
├── references/         # 可选：按需读取的文档
├── scripts/            # 可选：shell 执行的脚本（代码本身不进上下文）
└── assets/             # 可选：模板、图片等产物素材
```

附属文件索引有界：最深 4 层、最多 200 条，跳过 `.git` / `node_modules` / 构建产物等噪音目录，`SKILL.md` 自身不算附属资源。

## frontmatter 字段

| 字段 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | 1–64 字符，小写字母 / 数字 / 连字符 | 应与父目录名一致 |
| `description` | 是 | 1–1024 字符 | 模型唯一的触发路由信号 |
| `license` | 否 | 短字符串 | 技能许可 |
| `compatibility` | 否 | ≤500 字符 | 环境要求，如 `Requires Node 18+` |
| `metadata` | 否 | 缩进 `key: value` 块 | 任意附加元数据 |
| `allowed-tools` | 否 | 空格分隔的工具名 | 激活后本 turn 放行的工具（`Bash(git:*)` 这类括号作用域不解析） |
| `implicit` | 否 | `false` / `no` / `0` / `off` | 置位后仅允许 `/<技能名>` 显式调用 |

## 编写一个技能

````markdown
---
name: my-skill
description: 一句话说明何时该用这个技能（模型只看这句）。当用户要求 X 或提到 Y 时使用
---

# 规则

- 第一条规范

# 工作流

1. 第一步
2. 第二步

# 深入阅读

- 领域甲的全部细节：`references/domain-a.md`
- 领域乙的全部细节：`references/domain-b.md`

# 禁止

- 不要做的事
````

写描述时想象「模型只读这一句话来决定是否调用」——具体、可判断，并显式列出适用语境。正文保持精简，细节拆到 `references/`；引用保持一层深（`SKILL.md` 直接指向附属文件），不要二级转跳。

## 上下文生命周期

- **免压缩**：`skill` 工具结果与 `/<技能名>` 注入的用户记录在上下文压缩时完整保留，不被摘丢——技能规范必须贯穿整个会话。
- **去重**：同一轮内重复激活同一技能只回一条短回执，不重复占额。
