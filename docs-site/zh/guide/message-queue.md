# 消息队列

一个会话同时只有一个活跃 turn。活跃期间你继续打字发送，消息会进队列排队，前一条结算后自动接力下一条——不再弹「已有任务在进行」把你挡回来，也不会丢消息。零依赖实现在 `util/agent/queue.mjs`。

## 行为

- **入队**：活跃 turn 期间提交 → 回执 `turn_queued`（带 `position` 队内位置与 `input` 原文），客户端在输入区上方画出紧凑队列条
- **接力**：前一条 turn 结算（`turn_completed` / `turn_failed` / 中止都算结算）后，队列非空即自动泵下一条；轮到它时才真正开跑，事件写进它自己那条 SSE 流
- **幂等**：每条提交带 `opId`（网页端生成，服务端缺省时补一个）。重复 `opId` 返回同一条回执、不开第二条流、不重复执行——网络重发不会让你的一句话跑两遍
- **无人认领也跑完**：排队期间客户端断开，轮到它时照常执行，事件丢弃（你确实发了这条，只是不看结果了）
- **侧边对话不入队**：`/btw` 与主对话的互斥语义保持 409 原样

## 状态机

`queued`（等待）→ `running`（正在跑）→ `done` / `failed`（内存终态）；`held` 是用户显式挂起，要 promote 才继续。

落盘 `<数据目录>/queue.json`（临时文件 + rename 原子写），只持久化 `queued` / `running` / `held` 三态，`done` / `failed` 落盘前剪掉。队列文件损坏时按空队列处理并告警，不会因为文件坏掉挡住你发言。

重启恢复：进程被杀在半路的 `running` 回落 `queued` 由泵重跑；`held` 原样保留。单条会话队列上限 200 条。

## 操作入口

| 端 | 操作 |
| --- | --- |
| 网页 | 输入区上方队列条：看位置与原文、立即发送、移除 |
| 终端 | `/queue`（列出）/ `/queue send <序号>`（挪到队首立即发送）/ `/queue drop <序号>`（移除）/ `/queue clear`（清空） |
| HTTP | `GET /api/agent/queue/:id`、`POST /api/agent/queue/promote`、`POST /api/agent/queue/remove` |

已在执行的那一条不给远端删：删了就没有流能收它的结果，只能走停止（`POST /api/agent/abort`）。移除等待中的项会往它那条流推 `turn_cancelled`（`reason: 'removed'`）。

## 什么时候会感觉不到它

会话空闲时提交就是普通 turn，压根不进队列；只有「上一条还在跑」这一种情况会排队。排队期间你可以继续改输入框、切会话、甚至停下来看队里第几条是什么——接力用的是你当时那条请求的原文快照（模型 / 权限档 / 思考开关都在里面）。
