# 自定义提供方

除内置的美团 LongCat 外，可添加任意 **OpenAI 兼容** 或 **Anthropic Messages** 上游。

## 添加

网页设置 → 提供方 → 添加自定义提供方：

1. 填 Base URL 与 API Key（密钥格式实时校验）
2. 「发现模型」拉取上游模型目录（只读），勾选要加入的模型
3. 保存后模型选择器按提供方分组展示，`/api/chat` 与 Agent Loop 均可选用

## 路由规则

- 显式传 `provider` 优先；未传时按模型 ID 反查所属提供方；未知模型仍回退内置提供方
- 内置提供方只读；自定义提供方存储于 `<数据目录>/providers.json`（原子落盘，含密钥，不提交仓库）

## 故障转移

配了多个提供方且模型目录有交集时，主提供方返回 **429 限流 / 5xx 服务端错误 / 网络失败** 后，自动切换到提供同一模型的其它提供方重试——对话不中断，用户看不到错误。对应上游「自动轮换账号」能力的本地化实现。

- **只在连接期切换**：上游还没发出任何内容时才能换路；已经开始转发字节后的失败按既有行为传播（客户端已收到部分内容，不能透明换路）
- **不转移的错误**：400 / 401 / 402 / 403 / 404 / 422 原样报出——那是配置、鉴权、计费问题，换路只会掩盖真实原因
- **候选规则**：模型目录包含当前模型、配了 API 密钥、本次请求还没试过的其它提供方（内置提供方优先）；一次请求链内不重复踩同一家
- **turn 内粘性**：同一轮对话切换成功后沿用新提供方，避免两家来回抖动；用量记账归属真实产出 token 的那一家，失败的尝试无 token 消耗、不记账
- **参数**：`providerFailover`（缺省开启）与 `providerFailoverMaxAttempts`（含首次，缺省 3，钳制 1–5），设置页「故障转移」面板或环境变量 `AURORAAGENT_FAILOVER` / `AURORAAGENT_FAILOVER_MAX_ATTEMPTS` 覆盖
- **可感知**：网页落一条提示（「已切换提供方：A → B（上游限流，第 1 次尝试）」），终端打单行；判定与编排见 `util/llm/failover.mjs` 与 `util/llm/provider.mjs`

## 协议差异

`util/wire.mjs` 负责把内部统一的 OpenAI 形状（含 `tool_calls`）翻译成目标协议：Anthropic 线路的 `system` 抽离、`tool_use` / `tool_result` 块转换、SSE 帧翻译（`input_json_delta` → `tool_calls` delta），前端与 Loop 因此只需认识一种帧格式。
