# 屏幕操作（computer_use）

`computer_use` 让模型看你的屏幕并操作前台图形界面：先截图观察，再按截图里的像素坐标点击、输入、按键、滚动、启动应用。按 macOS 零依赖子集实现在 `util/agent/computer.mjs`。

## 能力边界

这个子集只拼 macOS 内置命令，不引第三方二进制、不写原生扩展：

- `osascript`（System Events）取窗口边界、派发点击 / 输入 / 按键 / 滚动
- `screencapture -R<x,y,w,h>` 截图，`sips -Z 1568` 缩放到长边 1568，超 1.5MB 转 JPEG 逐级降质
- 截图落盘 `<数据目录>/shots/<会话 id>/<时间戳>.png`，删除会话时整目录清掉

刻意不做（上游这些是 Windows / Linux 专属或需要原生扩展）：UIA / AT-SPI 控件树适配、原生窗口直达输入、后台常驻观察循环。所以观察通道只有「截图 + 坐标」这一条——模型看不到按钮叫什么，只能按像素位置猜，这也是为什么标准流程强制「先 observe 再动手」。

## 门控与授权

- 仅 **Ultimate** 模式收录 `computer_use`；Minimal / Standard 没有这个工具
- policy 默认 `ask`：**每次调用都要你显式确认**，「激活别的应用」这种抢前台的动作同样不得静默提权
- 调用前先探测两项系统授权，任一项缺失就返回中文指引（说清开关在哪、改完要重启），而不是对着黑屏反复重试：
  - 辅助功能：系统设置 → 隐私与安全性 → 辅助功能
  - 屏幕录制：系统设置 → 隐私与安全性 → 屏幕录制

## 一次调用长什么样

一次调用就是一次「作用域控制会话」：声明作用域（目标应用，省略则取当前前台应用的窗口）→ 批量动作（单次上限 40 个）→ 逐条回执 → 观察新鲜度提示。

| 动作 | 参数 | 效果 |
| --- | --- | --- |
| `observe` | — | 截图并按目标窗口裁剪（拿不到边界就整屏），图片随工具结果返回给模型 |
| `click` / `double_click` / `right_click` | `x` `y` | 屏幕全局坐标点击（左上为原点） |
| `type` | `text` | 输入文本，换行用回车键代打 |
| `key` | `key` | 按键，如 `return` / `tab` / `escape` / `up` / `cmd+c` |
| `scroll` | `dx` `dy` | 滚动量，`dy` 负值向上 |
| `wait` | `ms` | 等待，上限 5000ms |
| `open_app` | `app` | 激活指定应用（需要「自动化」权限） |

你在网页上能看到截图缩略图，点开放大；终端只展示路径与尺寸摘要。截图同时作为多模态 tool result 进模型上下文（OpenAI `image_url` / Anthropic `tool_result` image block），所以后续轮次里模型仍「记得」自己看过什么。

中止（停止按钮 / `Ctrl+C`）会级联取消：不再派发后续动作，并杀掉正在跑的子进程，不留野进程。

## 什么时候别用

批量重复劳动（同样的点击做一百次）不适合交给它：每次调用都要确认，而且模型对坐标的判断会随界面变化失效。界面一变就重新 `observe`，别拿旧截图点新界面。
