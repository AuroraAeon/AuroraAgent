# 提示缓存

提示缓存让上游对「不变的请求前缀」命中缓存：系统提示、工具定义、长对话的历史部分通常逐轮原样重发，命中后按缓存价计费，首 token 延迟也更低。AuroraAgent 按协议自动插桩，无需手工标注。

## 开关

两道门同时满足才启用，任一不满足时请求字节与不接入时逐字节一致（有测试断言）：

| 条件 | 位置 | 缺省 |
| --- | --- | --- |
| 提供方声明支持 | 提供方编辑器的 `capacity.supportsPromptCache` | 不声明（未声明一律按不支持处理） |
| 配置档位 | `promptCache`：`auto` / `off` | `auto` |

不认 `cache_control` / `prompt_cache_key` 的线路多发一个字段就是 400，因此「未声明」绝不代开；要开由用户在提供方编辑器里显式勾选。档位改下一轮请求即时生效。

## 断点位置

**Anthropic Messages 线路**

- system 改为块数组形态，稳定前缀收尾打 1 个断点
- `tools[]` 末项打 1 个
- 对话尾部打 2 个：最后一条用户消息、倒数第二条 assistant 消息
- 合计守上游 4 个断点的上限

**OpenAI 兼容线路**

- 带 `prompt_cache_key`：对提供方 id + 模型 + 稳定系统段取 sha1 的前 32 位十六进制——确定性且跨轮稳定，同会话连续轮次因此命中同一缓存分区
- 请求体其它部分保持字节稳定（`deferred` 标记的工具仍不进顶层 `tools[]`），前缀一个字节都不抖

## 用量可见

提示缓存命中与写入量进用量账本（`cachedTokens` / `cacheWriteTokens`），设置页用量面板据此展示：总计一行条件展示（全零不占位），「最近请求」表加「缓存」列。这两个数**不并进输入列**——它们是计费口径的另一维，混进去会让用量面板对不上账单。
