# 规则

规则把「项目约定」按条件注入系统提示：工作目录怎么组织、提交信息怎么写、哪些目录不许动。约定写一次，之后每一轮都在场，不必每次对模型复述。

规则与技能的分工：技能是**按需触发**的能力包（模型或用户显式调用才加载正文）；规则是**常驻或按路径生效**的规范。因此规则没有调用入口，只有激活判定；也正因常驻，它必须受 token 预算治理。

## 三个来源

| 来源 | 路径 | 优先级 |
| --- | --- | --- |
| 项目宪法 | `<工作目录>/AGENTS.md` | 高（无 frontmatter 时整篇恒生效） |
| 项目规则 | `<工作目录>/.auroraagent/rules/*.md` | 中 |
| 个人规则 | `<数据目录>/rules/*.md` | 低 |

同名时后者覆盖前者，项目约定优先于个人约定。

## 文件格式

Markdown + 宽松 YAML frontmatter（与技能同规约）：

```markdown
---
name: typescript-conventions
description: TypeScript 代码约定：类型优先、禁 any、命名规则
paths: ["src/**/*.ts", "web-ui/src/**/*.tsx"]
---

正文即注入系统提示的规则全文。
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 规则名，同时是开关表的键 |
| `description` | 是 | 一句话说明；预算超限降级展示时唯一的识别信号 |
| `paths` | 否 | glob 数组，条件激活；语义见下 |
| `always` | 否 | `true` 时无视 `paths` 恒生效 |

缺 frontmatter、`name` / `description` 为空、正文为空，这条文件按不存在处理（加载告警会说明原因）。`description` 上限 1024 字符、正文上限 500 行，超出给软告警不阻塞。

## paths 条件激活

`paths` 决定「这一轮碰到的文件算不算候选」——候选路径来自用户输入里提到的文件与会话记录里进过上下文的文件，最多取 64 条。

| 写法 | 语义 |
| --- | --- |
| 省略 `paths` | 恒生效（没有这个键就不进入条件求值） |
| `paths: []` | 显式关闭（单独关掉一条规则，但保留文件与开关状态） |
| 有 `paths` 但无候选路径 | 不激活（没有证据就不激活路径规则，保守） |
| 类型非法 | fail-open，按恒生效处理（坏数据不该静默吞掉规则） |
| `always: true` | 无视 `paths` 恒生效 |

glob 匹配是自实现的 picomatch 子集：`*` 不跨 `/`；`**` 跨目录任意层（含 0 层）；`?` 单字符；`[abc]` `[a-z]` `[!abc]` 字符类；以 `/` 开头锚定工作目录根，否则按「任意目录下」匹配；以 `/` 结尾表示目录，其下皆中；点文件默认参与匹配。

## token 预算

规则正文常驻上下文有 4000 token 预算：激活规则的正文总量超出时，超出的部分降级为 name + description 一行——绝不整块丢弃（一条约定被静默丢掉，比占点额度危险得多）。

## 开关

| 入口 | 用法 |
| --- | --- |
| 终端 | `/rules` 列出（来源 / 条件 / 当前是否激活）；`/rules on <名称>` 开；`/rules off <名称>` 关 |
| 网页 Composer | `/rules` 家族命令，与终端同解析 |
| HTTP | `GET /api/settings/rules` 回报发现到的规则清单与开关表现值；`POST` 整表替换开关 |

规则文件本身在文件系统里编辑，开关表只是开 / 关；下一轮请求即时生效。
