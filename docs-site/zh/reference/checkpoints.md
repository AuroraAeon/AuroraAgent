# 检查点与回滚

每个用户轮次开始前，AuroraAgent 会给工作目录拍一张快照（检查点）。之后可以整体回滚到那一照，而会话历史照样留着——对话里积累的上下文不丢，代码回到轮次开始前的样子，可以换个思路重来。

快照只在顶层用户轮拍摄：子代理的改动算父轮的，侧边对话（`/btw`）不落盘、无从回滚，因此也不拍。快照失败只告警，不挡这一轮。

## 两种快照路径

按工作目录是不是 git 仓库自动选择，无需配置：

| 路径 | 条件 | 快照内容 | 存放位置 |
| --- | --- | --- | --- |
| git 快照 | 工作目录是 git 仓库 | 工作区全部改动，含未被 `.gitignore` 排除的未跟踪文件 | 仓库内的私有 ref |
| 内容镜像 | 非 git 目录 | 本轮 `write_file` / `edit_file` 落笔前被改文件的原内容 | `<数据目录>/backups/<会话 id>/<轮次>/` |

### git 快照

- 快照钉进私有命名空间 `refs/auroraagent/checkpoints/<会话 id>/<轮次>`：对用户不可见（不出现在 `git stash list`），但让快照对象可达、不被 git 回收
- 未跟踪文件补成第三父提交，因此还原时新建的文件也能一起恢复
- 用一份跨轮持久化的 scratch index，git 的 stat 缓存能跳过「自上一轮没变过的文件」，不必每轮把整个工作区重新哈希
- 工作区干净且无未跟踪文件时，退化为 HEAD 检查点（记录当前位置，回滚即回到这个提交）

### 内容镜像

- 只镜像被动过的文件，不是整个工作区，大仓库也不会炸
- 新建的文件记一条「原本不存在」，回滚时照单删回
- 代价：`shell` 工具在进程内部造的文件不在管辖内

## 回滚

回滚默认**只动工作区文件，不动对话**——对话往往正是最有价值的产物，代码回滚后可以换个思路重来。要连对话一起裁剪需显式选择。

- 网页与终端回滚前都有 diff 预览：列出这一轮之后动过的文件，先看再决定
- git 路径的回滚走事务：先给「当前」工作区拍一张私有快照，再应用目标检查点；应用失败自动把当前状态复位，只有复位也失败才抛错
- 拒绝在「分支已经往前走过」的仓库上恢复：`reset --hard` 会把那些提交悄无声息地推出分支，宁可拒绝也不毁历史
- 对话裁剪保留该轮用户消息、删掉其后全部记录；轮次越界时原样返回并给出中文原因

## 网页入口

用户消息行悬停出现「回滚到此」钮，点击弹出预览：默认只回滚文件，「同时把对话裁剪到此轮」需显式勾选。生成中的会话与侧边对话不可回滚。

## 终端命令

| 命令 | 作用 |
| --- | --- |
| `/checkpoint` | 列出本会话检查点（轮次 / 时间 / 说明） |
| `/checkpoint diff <轮次>` | 回滚前预览：列出会动的文件 |
| `/checkpoint restore <轮次> [chat]` | 回滚；带 `chat` 才连对话一起裁剪 |
| `/checkpoint clean` | 清理本会话全部检查点 |

## HTTP API

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/agent/checkpoints?sessionId=` | 列出检查点（含快照路径类型） |
| `GET /api/agent/checkpoints/preview?sessionId=&turnIndex=` | 回滚预览：该轮之后动过的文件 |
| `POST /api/agent/checkpoints/restore` | 回滚；`restoreFiles`（默认 true）/ `restoreChat`（默认 false） |
| `DELETE /api/agent/checkpoints` | 清理本会话检查点（清 ref 与镜像备份） |

## 限制

- 每会话最多保留 40 个检查点，超出从最旧的开始删
- 删会话时清 git 私有 ref 与镜像备份目录
- 会话从未被显式删除时，scratch 目录靠 14 天年龄回收兜底
- 检查点创建成功会推 `checkpoint_created` 事件（SSE 订阅方可见）
