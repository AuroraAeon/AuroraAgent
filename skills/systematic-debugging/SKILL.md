# 系统化排错技能

定位与修复 bug 时遵循本流程。目标是用最少的改动找到根因，而不是让症状消失。

## 规则

- 先复现，再修复：没有稳定复现路径之前不改代码。
- 一次只改一个变量：同时改多处即使好了也不知道为什么好了。
- 假设必须可证伪：每个假设都要说明「什么现象出现 / 消失能证明它对」。
- 修复后补回归：能自动化的验证就落成测试，不能自动化的写清手工验证步骤。

## 工作流

1. 复现：最小步骤稳定触发问题，记录确切现象（报错、输出、退出码）。
2. 收窄：二分定位——注释掉一半、换输入、缩小数据范围，把嫌疑圈到最小单元。
3. 假设：列出可能原因，按「先验概率 × 验证成本」排序；对每个假设写明证伪条件。
4. 验证：用日志、断点、最小脚本验证假设；证伪的划掉，新的补上。
5. 修复：针对根因做最小修复；顺带检查同类模式是否有同样问题。
6. 回归：跑相关测试；若缺陷此前无测试覆盖，补一个能失败在旧代码上的测试再修复。

## 禁止

- 禁止盲目试错（改一处试试、不行再改一处）。
- 禁止修复症状而留下根因（例如把报错吞掉让日志干净）。
- 禁止在原因不明时重构「顺便优化」——排错期只做与根因相关的改动。
