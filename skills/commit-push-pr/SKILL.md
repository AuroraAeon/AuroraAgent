# 提交 · 推送 · 开 PR

把当前工作区的改动一次性送到远端并开出 Pull Request。全程幂等可重入：任一步失败说清原因与下一步，不要静默跳过。

## 规则

- 先看现状再动手：`git status`、`git diff`、`git log --oneline -5` 三连，确认改动范围、风格与基线分支。
- 只提交与本次任务相关的文件；无关改动（配置、临时产物、密钥文件）明确提示用户，不顺手 `git add -A`。
- 提交信息用中文，主题分隔冒号用半角 `:`；正文说清「为什么」而不是复述 diff。
- 每个提交尾部加归属 trailer（保持仓库既有约定，没有才加）：
  - `Co-Authored-By: AuroraAgent <noreply@auroraagent.local>`
- PR 标题与提交主题一致；正文按「改动内容 / 动机 / 验证方式 / 风险与回滚」四段写，验证方式要写真实跑过的命令。
- 基线分支先确认（`main` / `master` 以远端默认为准），不要凭猜测；远端不存在时说明并停下，不擅自创建。
- 推送与开 PR 用仓库既有的认证方式；失败时把上游原话带给用户，不要改写。
- 密钥、 token、 `.env` 一类文件永不进提交；发现已被跟踪立即提示用户处理。
